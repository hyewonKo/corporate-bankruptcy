## 1. 연구 배경

### 기존 조기경보의 한계

Altman(1968)의 Z-score 이후 수십 년간 부실 예측 연구는 재무비율 기반 분류 정확도 경쟁에 집중해왔다. 그런데 세 가지 근본적인 문제가 해결되지 않은 채 남아있다.

첫째, **재무제표는 늦다.** 분기에 한 번 나오고 이미 일어난 일을 반영한다. 실제 부실이 시작되는 시점보다 6~18개월 뒤에야 재무제표에 나타나는 경우가 많다.

둘째, **경보를 울린 다음이 없다.** 기존 연구는 "위험하다"는 알림에서 끝난다. 경보 이후 어떤 개입이 효과적인지는 거의 다루지 않는다.

셋째, **모델이 왜 그런 판단을 했는지 알 수 없다.** 블랙박스 모델이 "회생 불가"라고 분류해도, 그 근거를 모르면 실무자가 쓸 수 없다. 근거 없는 처방은 실행되지 않는다.

> "모델이 맞는 것보다, 왜 맞는지 설명할 수 있는 것이 실무에서 더 중요하다."

### XAI 없는 LLM, LLM 없는 XAI의 한계

XAI(SHAP)만 있으면 결과물이 숫자와 그래프다. 의사결정자가 SHAP 막대그래프를 보고 스스로 해석해야 하는데, 실무에서 이걸 바로 쓰기 어렵다.

LLM만 있으면 일반론이 나온다. "유동성을 개선하세요, 비용을 줄이세요" 같은 뻔한 처방이다. 기업 특화 맥락이 없으면 LLM은 교과서를 쓴다.

**XAI가 LLM의 입력을 날카롭게 만든다.** SHAP 값이 있어야 "이 기업은 특히 재고자산 회전율이 문제고, CFO 교체가 주요 선행 신호였다"는 기업 특화 처방이 가능하다. 둘의 결합이 이 프로젝트의 핵심 구조다.

## 2. 핵심 연구 질문

> **비재무 선행 신호로 재무제표보다 얼마나 일찍 경보를 울릴 수 있는가?**
> **오류 비용의 비대칭성을 반영한 동적 임계값은 총 손실을 얼마나 줄이는가?**
> **XAI로 분해한 회생 근거가 LLM 처방의 품질을 실제로 높이는가?**

---

## 3. 연구 목적

세부 목표는 다음과 같다.

- **선행성 실증** — 비재무 신호 조합이 재무비율보다 평균 N개월 앞서 부실을 감지함을 확인
- **동적 임계값 설계** — 거시 환경·사용자 유형·기업 규모별로 임계값을 조정하는 최적화 프레임워크 구축
- **회생 분류 + XAI** — 경보 이후 결과를 분류하고, SHAP으로 분류 근거를 기업별로 분해
- **LLM 처방 리포트** — SHAP 근거를 프롬프트로 구조화해 이해관계자별 자연어 처방을 자동 생성
- **검증 프레임워크** — XAI 근거가 있는 처방과 없는 처방의 품질을 비교하고, 실제 회생 사례로 사후 검증

---

## 4. 연구 가설

**H1. 비재무 선행 신호는 재무비율보다 부실을 조기에 탐지한다**

공시 빈도, CFO 교체, 감사인 변경 등 비재무 신호 조합은 재무제표 기반 모델보다 평균 4~6분기 앞서 부실 신호를 발생시킨다.  
*근거: 비재무 신호 선행연구, 이벤트 스터디 방법론*

**H2. 동적 임계값은 고정 임계값보다 총 오류 비용을 줄인다**

거시 환경과 사용자 유형에 따라 임계값을 조정하면, 고정 50% 임계값 대비 총 오류 비용이 통계적으로 유의하게 감소한다.  
*근거: 비대칭 손실함수 선행연구, Campbell et al.(2008)*

**H3. 경보 이후 행동 패턴이 회생 여부를 결정하며, XAI로 그 근거를 분해할 수 있다**

회생 분류 모델의 SHAP 분석을 통해, 어떤 변수가 회생/부실 판단에 기여했는지를 기업별로 설명할 수 있다.  
*근거: XAI 선행연구, SHAP 방법론 (Lundberg & Lee, 2017)*

**H4. XAI 근거를 포함한 LLM 처방이 일반 LLM 처방보다 실무 유용성이 높다**

SHAP 기여 변수를 프롬프트에 포함한 경우와 그렇지 않은 경우의 처방 리포트를 비교했을 때, 전자가 기업 특화성·실행 가능성 측면에서 우수하다.  
*근거: RAG·프롬프트 엔지니어링 선행연구, 전문가 평가*

## 5. 연구의 독창성

### 예측 → 설명 → 처방의 엔드투엔드 파이프라인

기존 연구는 예측 정확도에서 멈춘다. 이 프로젝트는 예측(부실 확률) → 설명(SHAP 기여 변수) → 처방(LLM 리포트)까지 하나의 파이프라인으로 연결한다. 각 단계가 독립 논문이 되고, 세 단계를 묶으면 엔드투엔드 의사결정 지원 시스템이 된다.

### XAI를 LLM의 컨텍스트로 활용

LLM에게 단순히 "이 기업 처방을 써줘"가 아니라, SHAP 상위 변수·섹터 맥락·거시 환경·분류 근거를 구조화된 프롬프트로 제공한다. XAI가 LLM의 일반론을 기업 특화 처방으로 전환하는 핵심 인터페이스가 된다.

### 검증 가능한 LLM 출력 설계

LLM 리포트의 신뢰성 문제를 회피하지 않고 정면으로 다룬다. 실제 회생 성공 기업에 대해 모델이 사후적으로 어떤 처방을 냈는지 검증하고, XAI 근거 유무에 따른 처방 품질 차이를 측정한다. "LLM 갖다 붙인 프로젝트"가 아닌 검증 가능한 프레임워크로 설계한다.

### 오류 비용 비대칭성을 모델 내부로

임계값을 외생적으로 고정하지 않고, 거시 환경 변수와 사용자 유형을 임계값 최적화 함수의 내생 변수로 취급한다. 자기실현적 예언(경보 자체가 부실을 유발하는 효과)을 과탐 비용 함수에 명시적으로 포함시킨다.

## 7. LLM 처방 리포트 설계

### 프롬프트 구조

```
[시스템 프롬프트]
당신은 기업 신용 리스크 전문가입니다.
아래 분석 결과를 바탕으로 {사용자 유형}을 위한
실행 가능한 처방 리포트를 작성하세요.

[컨텍스트 주입]
- 기업명: {company}
- 섹터: {sector}
- 경보 발령 시점: {alert_date}
- 회생 분류 결과: {classification}  ← LightGBM 출력
- 분류 신뢰도: {probability}

[XAI 근거 — SHAP 상위 5개 변수]
1. {변수명}: 기여도 {shap_value} ({방향: 회생↑/부실↑})
2. {변수명}: 기여도 {shap_value}
3. ...

[거시 환경]
- 현재 경기 국면: {macro_phase}
- 기준금리: {rate}
- 해당 섹터 크레딧 스프레드: {spread}

[요청]
위 근거를 바탕으로 다음을 작성하세요:
1. 현재 상황 요약 (3줄)
2. 핵심 리스크 요인 (SHAP 근거 기반)
3. 즉시 실행 액션 3가지
4. 30일·90일·180일 모니터링 지표
```

### 처방 매트릭스

| 분류 결과 | 대출 은행 | 경영진 | 채권단 |
|----------|----------|--------|--------|
| 자력 회생 가능 | 한도 유지 + 모니터링 강화 | SHAP 상위 변수 기반 우선 액션 | 관망 + 분기별 재검토 |
| 외부 개입 필요 | 담보 추가 요구 시작 | 전략적 투자자 접촉 개시 | 협약 조기 개시 검토 |
| 회생 불가 | 담보 실행 타이밍 최적화 | 손실 최소화 구조화 | 청산 절차 준비 |

## 8. 분석 유니버스

코스피·코스닥 상장 기업 중 관리종목 지정 이력 보유 기업을 포함해 구성한다.

| 섹터 | 대표 사례 | 선정 이유 |
|------|----------|----------|
| 건설·PF | 태영건설, 대우건설 | 레고랜드 사태 전후 — 비재무 선행 신호 + XAI 패턴 관찰 용이 |
| 바이오 | 코스닥 바이오 기업군 | 회계 이슈 빈발 — SHAP 변수 분포 vs. 타 섹터 비교 |
| 유통·소비재 | 이마트, 롯데쇼핑 | 내수 경기 민감 — 거시 연동 임계값 + LLM 처방 효과 검증 |
| 에너지·중공업 | 한국전력, HMM | 정책금융 개입 구조 — 과탐 비용 왜곡 + LLM 맥락 반영 가능 |

## 9. 기술 스택

```
Python 스택
├── 데이터 수집     pandas / FinanceDataReader / DART API / requests
├── 선행성 분석     scipy.stats / statsmodels (이벤트 스터디)

├── XAI             shap (SHAP 기여 변수 분해 + 시각화)
├── LLM 연동        openai / anthropic (GPT-4o / Claude API)
├── 프롬프트 관리   LangChain (컨텍스트 구조화 + 체인 관리)
└── 시각화·배포     plotly / seaborn / Streamlit
```

## 11. 포트폴리오 포지셔닝

> **1단계** — 비재무 선행 신호로 재무제표보다 빠른 경보  
> **2단계** — 오류 비용 비대칭성을 반영한 동적 임계값 설계  
> **3단계** — 경보 이후 회생 가능성 분류 + SHAP 기여 변수 분해  
> **4단계** — XAI 근거 기반 LLM 처방 리포트 자동 생성 + 검증  
> **통합 스토리** — 부실 예측에서 시작해 설명 가능한 처방까지, 엔드투엔드 의사결정 파이프라인을 설계한 프로젝트

두 가지 오류의 비용이 다르고 상황마다 달라진다는 사실을 모델 내부에 반영한다.  
SHAP으로 모델의 판단 근거를 분해하고, 그 근거를 LLM에 주입해 기업 특화 처방을 자동 생성한다.  
그리고 그 처방이 실제로 유효한지 사후 검증한다.  
이것이 기존 조기경보 연구와의 결정적 차이이며, 이 프로젝트 전체를 관통하는 핵심이다.
